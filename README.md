# Малый совет

Рабочее пространство для подготовки заседаний, учёта присутствия, обсуждения, голосования и оформления решений Малого совета Движения «Новые» в Москве. Программа опирается на предоставленный Устав и Регламент и образец протокола от 24 октября 2026 года. Бирюзовый интерфейс использует Unbounded.

## Запуск в Windows

1. Установите **Node.js 22.13 или новее** с [официального сайта](https://nodejs.org/). Рекомендуется актуальная LTS-версия. Python и установка npm-пакетов для новой версии не нужны.
2. Дважды щёлкните **start.cmd** в папке программы. Скрипт проверит Node.js и порт, запустит сервер и откроет браузер после его готовности.
3. При первом запуске создайте собственную учётную запись и пароль. Она получает организационные полномочия для первоначального заполнения состава. Добавьте настоящих членов совета; готовых общих паролей нет.
4. Оставляйте окно запуска открытым, пока работаете. Для остановки нажмите **Ctrl+C**. Повторный запуск сохраняет данные.

Если порт занят, скрипт завершится с понятной ошибкой и не будет останавливать чужую программу. Для выбора другого порта откройте PowerShell в папке проекта:

```powershell
$env:PORT = '8766'
.\start.ps1
```

Альтернатива запуску скриптом: `npm start` или `node server.mjs` из папки проекта. По умолчанию адрес — [http://127.0.0.1:8765](http://127.0.0.1:8765). Скрипт ничего не устанавливает и не изменяет системные настройки.

## Запуск в Linux

Нужен **Node.js 22.13 или новее** со встроенным SQLite. Установка npm-пакетов и Python не требуются.

В папке программы выполните:

```sh
sh ./start.sh
```

Затем откройте [http://127.0.0.1:8765](http://127.0.0.1:8765) в браузере. Сервер работает в текущем терминале; остановка — **Ctrl+C**. Скрипт можно вызывать из другого каталога, указав полный путь к нему. Он проверяет Node.js, наличие SQLite и допустимость порта; занятый порт не освобождает автоматически.

Для запуска как исполняемого файла:

```sh
chmod +x start.sh
./start.sh
```

Другой порт и доступ из доверенной локальной сети задаются переменными окружения:

```sh
PORT=8766 sh ./start.sh
HOST=0.0.0.0 PORT=8765 sh ./start.sh
```

Можно также задать `COUNCIL_DATA_DIR=/путь/к/данным`. База по умолчанию — `data/council.sqlite` в папке программы. Браузер в Linux открывается вручную; сценарий подходит и для сервера без графической оболочки.

## Первое заседание

Заполните состав совета, назначьте участникам индивидуальные пароли и создайте заседание: дата, формат, вид, место, а для экстренного заседания — обоснование срочности. Подготовьте повестку и материалы; отметьте её рассылку. Для очередного заседания учитывается срок в 24 часа. Внесение отметки в программу само по себе не рассылает сообщения участникам.

Отметьте присутствие: очно, дистанционно с подтверждением личности, отсутствует или покинул заседание. Наблюдатели учитываются отдельно и не получают права голоса. Установленная численность совета остаётся 16, кворум — 9, даже если карточки всех членов ещё не заполнены.

Откройте заседание и поставьте на голосование утверждение повестки. Далее выбирайте предусмотренную процедуру вопроса: программа определит требуемое большинство. Участники входят со своих устройств под своими учётными записями и голосуют лично. Секретарь фиксирует обсуждение, выступления и особые мнения. Закройте голосование и объявите результат; для вето и его преодоления предусмотрены отдельные действия. После заседания получите протокол и текст для публичного информирования, проверьте их перед отправкой.

Сведения о принятых решениях, внутренних комитетовах, поручениях, обращениях и показателях участия ведутся в соответствующих разделах. Материалы прикрепляются к заседанию и при необходимости к вопросу; скачивание доступно после входа. Нормативные проекты связываются единым предметом: первое чтение фиксирует одобрение концепции, окончательный текст вступает в силу после итогового решения. Для инициатив участников Движения отдельно учитываются пять подписей при направлении проекта и десять при предложении в повестку. Недостаточная посещаемость не приводит к автоматическому лишению мандата: дисциплинарное решение и возможность объяснений/апелляции требуют отдельной процедуры.

## Подключение других устройств

Обычный запуск доступен только с этого компьютера. Для осознанного запуска в доверенной локальной сети:

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '8765'
.\start.ps1
```

Участники открывают `http://<локальный-IP-компьютера>:8765` в своей сети. Скрипт не настраивает брандмауэр и переадресацию портов. Для доступа через интернет нужен отдельный HTTPS-сервер или доверенный HTTPS-прокси; обычный локальный HTTP-запуск для публикации в интернете не предназначен. Передавайте индивидуальные пароли участникам подходящим приватным способом.

## Данные и резервные копии

Новая версия хранит данные в **data/council.sqlite**. Каталог можно задать переменной `COUNCIL_DATA_DIR`; относительный путь отсчитывается от папки, из которой запущен сервер. Для полной резервной копии остановите сервер и скопируйте каталог `data` целиком в безопасное место. Восстанавливайте копию при остановленном сервере. Экспорт JSON полезен для просмотра/архивирования, но не заменяет полную копию каталога данных и не означает наличие автоматического обратного импорта.

Исходные Python-файлы, прежняя `council.db`, папка `ref` и документы требований сохраняются. Новый сервер не изменяет прежнюю базу и не импортирует её автоматически. Исторический протокол содержит неполные и несогласованные сведения о голосах, поэтому программа не создаёт из него вымышленные персональные бюллетени. Реальные данные можно перенести вручную после сверки.

Исходный текст Устава сохранён в `requirements/charter.txt`, извлечённый образец — в `requirements/protocol-example.txt`. Разбор норм и спорных положений — в `REQUIREMENTS.md`. Применяемые автоматические пороги должны соответствовать принятой советом редакции Устава; изменения исходного Google-документа не загружаются автоматически.

Unbounded загружается через Google Fonts, поэтому для него нужен доступ к интернету. При недоступности используется резервный шрифт; сами данные заседаний остаются локальными.

## Проверка программы

```powershell
npm test
```

Тесты используют встроенный `node:test`, отдельную временную базу и свободный локальный порт. Они не удаляют рабочие данные. Проверяется логика порогов и процедур, а также полный HTTP-сценарий: первоначальная настройка, права доступа, кворум, индивидуальные голоса, фиксация результата, равенство голосов и повторный тур выборов председателя, тайна бюллетеней в API и экспорте, преодоление вето 11 голосами, создание группы и поручения из принятого решения, два чтения, материалы с безопасными именами, сроки и повторная рассылка изменённой повестки, подписи инициатив, экранирование протокола и сохранение после перезапуска. Для HTTP-теста среда должна разрешать локальные сокеты.


## Открытая приёмная и быстрый протокол

Публичная страница `/public` принимает обращения и инициативы без входа. Для обращения выбираются Малый совет, конкретный член, должность (председатель/секретарь) или действующий внутренний комитет. Заявитель получает личный код для проверки статуса и чтения ответа. Код и контакты не публикуются. Отправка ответа по email или Telegram автоматически не производится.

Секретарь открывает «Публичные заявки», принимает заявку в реестр и отвечает. Адресат сохраняется: обращения члену поступают этому члену, должности — соответствующей должности, комитету — указанному комитету. Личные контакты поступивших заявок доступны председателю и секретарю. Индивидуальная идея регистрируется как предложение для рассмотрения; она не подменяет формальный порядок инициативных групп и проверки подписей.

В заседании нажмите «Вести протокол» или вкладку «Быстрый протокол»: выберите вопрос и выступающего, тип записи, введите текст и нажмите Ctrl+Enter. Черновик хранится в этой вкладке браузера; после отправки запись сохраняется на сервере. Тип «Формулировка решения» обновляет текст для голосования только до его открытия. На том же экране доступны голосование, объявление результата, следующий вопрос и предпросмотр. Исправления сохраняют историю; убранные записи исключаются из печатного протокола. После закрытия заседания редактирование блокируется.

В интерфейсе и реестре рабочие группы переименованы во внутренние комитеты по запросу пользователя. Исходный текст Устава и принятые исторические протоколы не переписываются. Внутренние комитеты Совета сохраняют статус внутренних органов и не подменяют исполнительные комитеты Движения.
